## Мета
Мінімалістичний таймер на один екран за фінальним дизайном із Figma: чорна сторінка, по центру великий білий час `mm:ss` (IBM Plex Sans SemiBold) і під ним ряд матових скляних кнопок Start / Stop / Reset, кожна з підписом та іконкою (play / pause / reset), без картки. Рахує вгору від `00:00`, працює від 320 px до десктопа. Фон чисто чорний; лише за рухомим вказівником лишається м'який «димний» слід (синій → фіолетовий → смарагдовий), що розпливається й зникає за ≈ 1.7 с: власний легкий WebGL-шейдер.

## Екрани / частини
Один екран, без роутингу.

   Кожна кнопка = підпис + іконка праворуч від нього (Start — play ►, Stop — pause ‖, Reset — reset ↺).

- `App` — `<main>` на всю висоту в'юпорта (`min-height: 100dvh`), блок по центру по обох осях, поля ≥ 16 px з усіх боків.
- `Background` — декоративний шар (`aria-hidden="true"`): чорний фон і WebGL-канвас із димним слідом вказівника на весь в'юпорт під контентом, див. «Анімований фон».
- `Timer` — блок із цифрами й кнопками, єдиний функціональний компонент, без обов'язкових props:
  - заголовок `<h1>Timer</h1>` — лише для скрінрідерів: візуально прихований (клас `.visually-hidden`, див. «Доступність»); видимого слова «Timer» немає, верхній елемент блока — дисплей;
  - дисплей `mm:ss`, завжди в один рядок;
  - ряд кнопок: слот основної дії (`Start` ↔ `Stop`, один і той самий `<button>`) і `Reset`; на екрані лише доступні дії (див. «Поведінка → Кнопки»); кожна кнопка — підпис + іконка праворуч від нього (Start — play, Stop — pause, Reset — reset; inline SVG, декоративні);
  - візуально прихований live-регіон `role="status"` (див. «Доступність»);
  - логіка: reducer / хук `useTimer` з переходами з таблиці нижче (це джерело правди) + чиста функція `formatTime(ms) → "mm:ss"`.
- Видимого рядка стану немає: у Figma його нема (Рішення 9, «Відкриті питання» 3).
- Мова UI англійська (лейбли з ТЗ та Figma): `<html lang="en">`, `<title>Timer</title>`.
- Runtime-залежності: `react`, `react-dom`, `@fontsource/ibm-plex-sans` (лише latin 400 і 600; Рішення 9). Фон — власний WebGL-шейдер, іконки — inline SVG: бібліотек для них немає. Залишки шаблону Vite (логотипи, counter, демо-стилі) прибрати.

## Стани

### Що на екрані
| Стан | Дисплей | Кнопки (усі в одному стилі; кожна — підпис + іконка) |
|---|---|---|
| idle | `00:00` | `Start` + play (одна, на всю ширину блока) |
| running | минулий час, +1 щосекунди | `Stop` + pause · `Reset` + reset (дві рівні колонки) |
| paused | застигле значення (може бути `00:00`, якщо Stop натиснуто через 400–1000 мс після старту) | `Start` + play · `Reset` + reset (розкладка як у running) |
| paused на ліміті `59:59` ¹ | `59:59` | `Reset` + reset (єдина, на всю ширину блока) |

¹ Див. Рішення 1.

Стан читається за набором кнопок і значенням дисплея; кольором і видимим рядком стану не передається.

### Переходи: стан × кнопка → новий стан
| Стан \ кнопка | Start | Stop (дія `pause`) | Reset |
|---|---|---|---|
| idle | → running, відлік від 0 | — | — |
| running | — (не перезапускає, не скидає точку старту) | → paused, значення фіксується | → idle, `00:00`, відлік зупинено |
| paused | → running, продовжує з того ж значення | — | → idle, `00:00` |
| paused на ліміті | — | — | → idle, `00:00` |

`—`: такої кнопки на екрані немає, тож і дії немає; стан не змінюється. Якщо така дія все ж надійде (подвійний клік, гонка рендеру), reducer її ігнорує.
Автоматичний перехід: running → paused на ліміті, щойно минулий час досягає `59:59`.
Терміни: видимий підпис кнопки зупинки — `Stop` (Рішення 9); у коді й назвах станів лишаються `pause` / `paused`: це відновлювана пауза, Start продовжує з того ж значення.

### Стани кнопок
- default, hover (тільки `@media (hover: hover)`), focus-visible, active (натиснута); на сенсорних екранах (`@media (hover: none)`) підпис і іконка яскраві вже за замовчуванням. Що саме змінюється в кожному стані — таблиця в «Візуальний стиль → Стани кнопок».
- Неактивних станів немає: дія, недоступна в поточному стані, просто не показується (див. «Поведінка → Кнопки»).
- loading / empty / error / success не застосовні: мережі й даних немає.

## Поведінка

### Модель часу (точність)
- Час береться з реального годинника, а не з підрахунку тіків:
  - `accumulatedMs` — накопичено за попередні запуски; `startedAt` — `Date.now()` на момент останнього Start або `null`;
  - `elapsed = accumulatedMs + (running ? Date.now() - startedAt : 0)`, знизу обмежено 0, зверху лімітом;
  - Start: `startedAt = now`. Stop (дія `pause`): `accumulatedMs += now - startedAt; startedAt = null`. Reset: `accumulatedMs = 0; startedAt = null`.
- Джерело — саме `Date.now()`: він зараховує й час сну ОС, як фізичний секундомір. `performance.now()` у частині браузерів цей час не рахує.
- Інтервал/таймаут лише запускає перерахунок. Він працює тільки в running, активний завжди щонайбільше один, крок ≤ 250 мс (або `setTimeout` до наступної межі секунди). Так секунди міняються вчасно й без пропусків.
- Stop зберігає значення з точністю до мс, без округлення до секунд.
- Відображення: `s = floor(elapsed / 1000)`, `mm = floor(s / 60)`, `ss = s % 60`, обидва з ведучим нулем до 2 цифр. `00:01` з'являється через 1 с після Start.
- Ліміт задано однією константою (`59:59` = `3_599_000` мс). Коли його досягнуто, `elapsed` фіксується на ліміті, стан → paused. `60:00` і більше ніколи не показується.

### Кнопки
- На екрані лише доступні дії (колонка «Кнопки» в таблиці «Що на екрані»).
- Слот основної дії — один і той самий `<button>`: той самий DOM-елемент, React його не перемонтовує. Він змінює лейбл, іконку й дію: `Start` (play) в idle і paused, `Stop` (pause) у running. Дві різні кнопки умовно не рендерити. На ліміті слот зникає.
- `Reset` — окрема кнопка. Вона з'являється в running і paused, на ліміті лишається єдиною (на всю ширину), в idle її немає.
- Порядок у DOM і візуально: основна → Reset.
- Захист від подвійних дій: після переходу під курсором чи пальцем може опинитися інша кнопка. Тому дії, що надходять протягом ≈ 400 мс після попереднього переходу, ігноруються (одна константа, напр. `ACTION_LOCK_MS = 400`). Вікно діє після переходів, ініційованих користувачем, і після автостопу на ліміті. При утриманні Enter повтори keydown (`event.repeat`) не активують кнопку (`preventDefault`). Guard від повторного Start у reducer'і лишається.
- Поява, зникнення й переміщення кнопок — перетікання 1 ↔ 2 кнопки, див. нижче. Кнопка, що зникає, одразу стає неінтерактивною (не клікається, поза Tab-порядком). Перетікання коротше за вікно ≈ 400 мс, тож після вікна анімація не блокує кліки по новій кнопці.
- Фокус — див. «Доступність → Керування фокусом».

### Перетікання кнопок 1 ↔ 2
Рішення LEAD (у Figma лише три статичні кадри): спокійне, без пружини. Замінює колишній морф з overshoot (Рішення 8, скасовано). Ще заспокоєно за запитом користувача (Рішення 11, 2026-10-05): м'який розгін і посадка, друга кнопка з'являється на місці, а не їде.
- Розкладки: «1 кнопка» (idle — `Start`; ліміт — `Reset`) — кнопка на всю ширину блока; «2 кнопки» (running, paused) — дві рівні колонки (≈ 281.5) з gap 20 px · k, основна ліворуч, `Reset` праворуч.
- idle → running: `Start` (той самий `<button>`, тепер `Stop`) стискається до лівої колонки, `Reset` з'являється на своєму місці в правій колонці.
- Reset → idle (з running чи paused): зворотне — `Reset` зникає на місці, основна кнопка (знову `Start`) розтягується на всю ширину.
- Автостоп на ліміті (running → ліміт): слот `Stop` зникає на місці, `Reset` розтягується з правої колонки на всю ширину (так само, як основна кнопка в переходах вище). Reset з ліміту → idle: `Reset` зникає, `Start` з'являється на всю ширину, на місці, без руху вбік.
- running ↔ paused: нічого не рухається, лейбл і іконка змінюються миттєво.
- Рух кнопки, що лишається (основна; на ліміті — `Reset`): тривалість 250 мс, крива `cubic-bezier(0.4, 0, 0.4, 1)`: м'який розгін і м'яка посадка, без різкого старту й без overshoot (крива не виходить за [0, 1]). Ширина змінюється через scale по X (колонка ↔ весь ряд) разом зі зсувом на нове місце.
- Вміст кнопки, що змінює ширину, не розтягується: підпис і іконка (одна група) отримують точний контр-scale по X, тож відхилення їхньої ширини від статичної ≤ 1% у будь-якому кадрі. Перший і останній кадри збігаються зі статичними розкладками: у кінці немає стрибка.
- Кнопка, що з'являється (`Reset` в idle → running): стоїть на своєму місці, без scale: `opacity` 0 → 1 за ≈ 190 мс із затримкою ≈ 50 мс (50 + 190 < 250: закінчується до кінця руху), зсув ≤ 8 px (× k) з боку основної кнопки. `Start`, що з'являється з ліміту, — те саме, але без зсуву.
- Кнопка, що зникає: одразу неінтерактивна (напр. `inert`) і лежить під кнопкою, що лишається; `opacity` 1 → 0 за ≈ 120 мс, зсув ≤ 6 px (× k) у бік кнопки, що лишається (з ліміту — без зсуву), без scale. Вікно 400 мс і правила фокусу не змінюються.
- Анімуються лише `transform` / `opacity`. Єдиний дозволений виняток у keyframes — колір обідка скла (див. «Візуальний стиль → Кнопки»): на кнопці, що змінює ширину, обідок плавно гасне за перші ≈ 20% часу, прихований до ≈ 50% і плавно повертається до 100% (без миттєвих вимикань). Кнопкам, що з'являються чи зникають, окремої анімації обідка немає: він іде з їхнім `opacity`. `width`, `left`, `flex`, `grid-template-*`, `filter`, `clip-path` не анімуються. Підказка (не вимога): кінцевий лейаут застосовується одразу, а рух — зворотний transform, що спадає до нуля (FLIP). Вимоги — критерій 18.
- Тривалість стану анімації в React (`BUTTON_MOTION_MS`) — 280 мс: трохи довше за рух (250 мс), щоб м'яку посадку не обрізало, і менше за вікно 400 мс.
- Цифри й висота блока (≈ 340) не рухаються (критерій 32).
- `prefers-reduced-motion: reduce` → переходи миттєві (обідок видно одразу).

### Клавіатура
- Tab / Shift+Tab ходять лише по видимих кнопках: основна → Reset.
- Enter / Space активують кнопку під фокусом; повтори keydown при утриманні (`event.repeat`) ігноруються.
- Глобальних гарячих клавіш немає.

### Анімації
- Цифри змінюються миттєво, без flip-анімацій, згасань і блимання.
- Анімуються: фон (слід диму, див. «Анімований фон»), перетікання кнопок 1 ↔ 2 (див. вище), заливка кнопок і колір підпису та іконки при hover / focus-visible / active (transition 150 мс; reduced-motion — без transition).
- На самих кнопках `transform` / `opacity` — лише для перетікання; єдиний виняток у keyframes перетікання — колір обідка скла. Натискання (active) змінює тільки заливку й яскравість підпису та іконки: без scale, зсуву й «набухання»; обідок не змінюється.

## Візуальний стиль
За фінальним Figma (Рішення 10): `Desktop - 1` (idle), `Desktop - 2` (running), `Desktop - 3` (paused), макет 1440×1024, де `k = 1`; для інших в'юпортів усі розміри множаться на `k` (формула — «Адаптивність»). Значення нижче точні, з Figma; «рішення LEAD» — те, чого у Figma нема.

- **Сторінка**: фон `#000000`, без картки, панелі й рамки. `html`/`body`: `background: #000`, `color-scheme: dark`, щоб при overscroll на мобільному не проглядав білий. Фон-шейдер — див. «Анімований фон».
- **Блок**: ширина 583 px (= W), вертикальний стек: дисплей (≈ 216) → gap 24 px → ряд кнопок (висота 100). Висота ≈ 340 px, однакова в усіх станах. По центру в'юпорта по обох осях.
- **Шрифт**: IBM Plex Sans через `@fontsource/ibm-plex-sans` (Рішення 9): self-hosted, імпортуються лише latin 400 і 600 (`latin-400.css`, `latin-600.css`), без запитів до Google Fonts, без інших ваг і сабсетів. Фолбек `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`.
- **Цифри**: IBM Plex Sans SemiBold (600), `font-size: 213.69px`, `line-height: 1.01` (101%), `letter-spacing: 0.002em` (0.2%), `#FFFFFF`; суцільний колір, без градієнта, відблиску й тіні. `font-variant-numeric: tabular-nums`, `white-space: nowrap`, по центру блока. Рядок цифр на всю ширину блока (у Figma текстовий бокс 583 × 216). Ширина рядка не залежить від цифр (критерій 13): якщо шрифт не дає однакової ширини цифр, кожна цифра стоїть у боксі фіксованої ширини. Цифри не анімуються.
  - Перевірка шрифту: природна ширина `00:00` має бути ≈ 583 ± 3 px (у Figma такий текстовий бокс). Якщо ні — розмір шрифту НЕ підганяти (213.69 — з Figma): цифри центруються в блоці 583, розбіжність записується в звіт builder'а.
- **Кнопки** (однакові в усіх станах, акценту немає):
  - висота 100 px; `border-radius: 23px` (звичайний); `border: 0`;
  - заливка `#6B6B6B` з непрозорістю 20% (`rgba(107, 107, 107, 0.2)`);
  - розкладки: idle і ліміт — одна кнопка на всю ширину блока (583); running і paused — дві рівні колонки ≈ 281.5 з gap 20 px, ряд на всю ширину блока (583), основна ліворуч, `Reset` праворуч;
  - ефект «скла» (Figma Glass, radius 4, light angle −45°): `backdrop-filter: blur(4px)` разом із `-webkit-backdrop-filter` + обідок скла;
  - **обідок скла**: тонка (1 px, не масштабується) світла лінія по контуру, яскравіша у верхньо-лівому й нижньо-правому кутах. Реалізація: два inset `box-shadow` — `inset 1px 1px 0 0` білий ≈ 0.22 і `inset -1px -1px 0 0` білий ≈ 0.17. На hover / active / focus обідок не змінюється. Під час перетікання кнопок (на кнопці, що змінює ширину: під scale по X лінія 1 px стала б тоншою чи товстішою) він плавно гасне за перші ≈ 20% часу, прихований до ≈ 50% і плавно повертається до 100%, без миттєвих вимикань (у keyframes, крім `transform` / `opacity`, анімується лише колір цієї тіні — дозволений виняток). У `forced-colors` обідка немає;
  - рекомендації: предки кнопок не створюють backdrop root (без `opacity` < 1, `filter`, `mask`, `will-change: transform` на обгортках), інакше `backdrop-filter` не бачить канвас; анімації й `opacity` перетікання — на самих кнопках. Приглушення підпису й іконки задається їхнім власним кольором / прозорістю, а не прозорістю кнопки чи обгортки групи (інакше воно множиться з fade-in / fade-out перетікання).
- **Вміст кнопки**: підпис, ПІСЛЯ нього іконка (праворуч); група «підпис + іконка» стоїть по центру кнопки по обох осях, іконка — на середній лінії рядка підпису.
  - підпис: IBM Plex Sans Regular (400), `font-size: 44px`, `line-height: 1.01`, `letter-spacing: -0.02em` (−2%), `white-space: nowrap`;
  - іконки: inline SVG з Figma — play у Start, pause у Stop, reset у Reset; рамка 32 × 40 у всіх трьох; декоративні: `aria-hidden="true"`, `focusable="false"`, доступне ім'я кнопки — лише текст. У слоті Start ↔ Stop іконка змінюється разом із підписом;
  - gap підпис → іконка: Start 6, Stop 4, Reset 4;
  - позиції (x від лівого краю кнопки, k = 1, допуск ±1.5 px):

    | Стан | Кнопка (ширина) | Підпис | Ліва межа рамки іконки |
    |---|---|---|---|
    | idle | Start (583) | 226 | 325 |
    | running | Stop (≈ 281.5) | 78 | 171 |
    | running | Reset (≈ 281.5) | 67.5 | 181.5 |
    | paused | Start (≈ 281.5) | 78 | 177 |
    | paused | Reset (≈ 281.5) | 67.5 | 181.5 |
    | ліміт | Reset (583) | група по центру (кадру в Figma нема) | — |

  - paused: Start у половинній кнопці має додатковий відступ зліва 6, тож підпис Start починається там само, де підпис Stop (x ≈ 78): текст не стрибає при Stop ↔ Start. В idle (одна кнопка на 583) цього відступу немає.
- **Стани кнопок** (Figma + рішення користувача для сенсорних екранів). «Білий @ N» — білий з альфою N:

  | Стан | Заливка | Підпис | Іконка | Інше |
  |---|---|---|---|---|
  | default | 20% | білий @ 0.4 | білий @ 0.3 | обідок скла |
  | hover (лише `@media (hover: hover)`) | ≈ 28% | 1.0 | 1.0 | transition 150 мс |
  | focus-visible | 20% | 1.0 | 1.0 | `outline: 2px solid #fff`, `outline-offset: 3px` |
  | active | ≈ 16% | 1.0 | 1.0 | без scale і зсуву |
  | сенсорні (`@media (hover: none)`) | 20% (active ≈ 16%) | 1.0 | 1.0 | білі за замовчуванням (рішення користувача) |
  | `forced-colors: active` | `ButtonFace` | `ButtonText`, без прозорості | те саме | рамка `1px solid ButtonText`, без обідка |

  - перехід кольору підпису й іконки 150 мс; перехід заливки ≤ 150 мс; reduced-motion — без transition;
  - обідок і геометрія на hover / active / focus не змінюються; scale немає.
- **Контраст** (прийняте рішення): див. «Доступність». Коротко: білий підпис і цифри ≥ 4.5:1; сірий підпис за замовчуванням ≈ 3.85:1 на заливці кнопки.
- **Фолбеки**:
  - без `backdrop-filter` (`@supports not (backdrop-filter: blur(1px))`, з урахуванням `-webkit-`) або з `prefers-reduced-transparency: reduce` — щільна темна заливка кнопок ≈ `#151515`–`#1C1C1C` (hover трохи світліша, active трохи темніша), без розмиття; обідок і кольори вмісту без змін. Білий текст на ній ≈ 15:1 і вище;
  - у `forced-colors: active` — системні кольори: кнопки з видимою рамкою (`border: 1px solid ButtonText`), підпис і іконка без прозорості, без обідка скла, focus ring видимий, фон-канвас прихований.

## Анімований фон
«Димний» шлейф курсора: власний WebGL1-шейдер у `<canvas>`, без залежностей (Рішення 10). Орієнтир — hero на shaders.com (за словами користувача): беремо лише ідею, коду й ассетів звідти немає. Увесь розділ — рішення LEAD (фону у Figma нема); значення з «≈» можна підкрутити, якщо критерії приймання виконуються (19–22, 26).

- **Шар**: `Background` — `position: fixed; inset: 0`, під контентом, `pointer-events: none`, `aria-hidden="true"`, фон шару `#000`; усередині один `<canvas>` на весь в'юпорт (`aria-hidden`, без `tabindex`). Скролу не додає. Під ним `#000` з `html`/`body`. Фон не залежить від стану таймера.
- **У спокої** екран чисто чорний (`#000`: жодних плям, віньєток чи зерна на чорному) — після завантаження, поки вказівник не рухався, і після того, як слід зник.
- **Слід**: при русі вказівника (`pointermove` будь-якого типу: mouse, pen, палець, що веде по екрану) за ним лишається широкий м'який слід, що розпливається й зникає.
  - Точки сліду: 40 × ≈ 44 мс → життя ≈ 1.7 с. Нова точка — не частіше ніж раз на ≈ 44 мс і лише якщо вказівник зрушив. Після зупинки вказівника екран знову чорний за ≈ 1.7–1.8 с; постійної «голови» під нерухомим вказівником немає.
  - Швидкий рух лишає суцільну гладку лінію, без «намистин». Вхід вказівника з іншого місця (вихід за вікно й повернення, новий дотик) починає нову лінію: відрізка від старої позиції немає.
- **Ширина й дифузія**:
  - радіус біля вказівника ≈ 11% меншої сторони в'юпорта (ширина на півяскравості ≈ 225 px при 1440×1024); профіль — чистий гаусів, без ядра й різкого краю, плюс слабкий ширший серпанок;
  - дифузія: з віком ділянка ширшає від ×1 до ≈ ×2.3 і блідне;
  - пікова непрозорість ≈ 70% (біля вказівника, у момент появи), далі плавно до нуля, без стрибка наприкінці життя;
  - зерно ≈ ±3.5% (симетричне, лише на димі; середня яскравість не росте);
  - форма трохи неправильна, як дим (повільний шум), а не ідеальна смуга.
- **Колір**:
  - колір ділянки задається в момент її появи й циклічно змінюється: синій `#2438C8` → фіолетовий `#6B35C8` → смарагдовий `#12936F` → синій, період ≈ 3.6 с; у сліду одночасно видно сусідні кольори;
  - з віком: синій і фіолетовий → сланцево-синій `#24476B`, смарагдовий → темний синьо-зелений `#17505A`, далі всі → нейві `#141B4D` → прозоре;
  - кольори ніколи не яскравіші за перелічені (див. «Яскравість»); теплих, рожевих і білих відблисків немає.
- **Яскравість — стримана; пріоритет контрасту** (критерій 26; перемагає палітру):
  - піковий смарагдовий `#12936F` — лише при непрозорості ≈ 70%: при 100% білий на ньому дав би ≈ 3.9:1, при ≈ 70% — ≈ 6.5:1 (із зерном). Синій і фіолетовий темніші (≳ 10:1);
  - білий текст (підписи й цифри) у найсвітлішій точці фону ≥ 4.5:1 — у будь-який момент анімації й за будь-якої позиції вказівника, зерно враховано. Якщо контраст не проходить, знижувати яскравість фону, а не міняти колір тексту;
  - фон не блимає: яскравість змінюється плавно, без стробування.
- **Рендер — легкий**:
  - один `<canvas>`, один fullscreen-трикутник / квад, один fragment-pass; без текстур, framebuffer'ів і post-process (bloom / blur), без fluid-симуляції; достатньо WebGL 1;
  - половинна роздільність: внутрішній розмір канваса ≈ 0.5× CSS-розміру, DPR не множиться (на Retina теж ≤ 1); канвас розтягнуто CSS на весь в'юпорт;
  - рекомендовано: контекст з `alpha: false`, `antialias: false`, `depth: false`, `stencil: false`, `powerPreference: "low-power"`;
  - цикл `requestAnimationFrame` працює лише поки слід живий: у спокої 0 кадрів (після зникнення сліду — один чорний кадр, далі rAF не запланований); наступний `pointermove` його будить;
  - пауза при прихованій вкладці (`visibilitychange` / `document.hidden`): rAF не крутиться; після повернення слід або домальовується (якщо ще живий), або канвас чорний;
  - `pointermove` — на `window` (passive): в обробнику лише запис координат і часу. `resize` перераховує розмір канваса й uniform'и, живий слід перемальовується одразу. У кадрі немає читання layout (`getBoundingClientRect`, `offsetWidth` тощо), DOM і стилі не змінюються;
  - ефект із cleanup: зупиняє rAF, знімає слухачі, звільняє GL-ресурси. StrictMode (подвійний mount) не лишає зайвих циклів, слухачів, канвасів і контекстів;
  - `webglcontextlost` → `preventDefault()`, ефект зупиняється, канвас прибирається, фон чорний (відновлення контексту необов'язкове). Помилка компіляції / лінковки шейдера → те саме, без throw і без помилок у консолі.
- **Фолбеки** (CSS-фолбека фону немає, Рішення 10):
  - без WebGL (немає контексту, контекст втрачено, шейдер не скомпілювався): канвас прибрано, фон чисто чорний; без помилок у консолі;
  - `prefers-reduced-motion: reduce`: ефект вимкнено — канваса немає, фон чорний, rAF не крутиться, на `pointermove` нічого не відбувається; перемикання налаштування «на льоту» вмикає й вимикає ефект;
  - `forced-colors: active`: фон прихований (`display: none`), сторінка в системних кольорах;
  - фолбек кнопок — див. «Візуальний стиль → Фолбеки».

## Адаптивність
Один коефіцієнт масштабування (рішення LEAD). Окремих брейкпоінтів для розмірів немає: флюїдний лейаут від 320 px.
- Ширина блока: `W = min(583px, 100vw − 32px, (100dvh − 32px) × 1.69)`, коефіцієнт `k = W / 583`. Усі розміри блока — значення Figma × k: цифри 213.69·k, підпис 44·k, іконка 32·k × 40·k, відступи підпис → іконка 6·k / 4·k, відступ Start у paused 6·k, висота кнопки 100·k, радіус 23·k, gap цифри → кнопки 24·k, gap колонок 20·k. Не масштабуються: `backdrop-filter: blur(4px)`, обідок скла 1 px, outline фокуса (2 px, offset 3 px). Зручно мати одну змінну-«піксель» `--u: calc(min(…) / 583)` і писати розміри як `calc(N * var(--u))`. Розміри в `rem` і окремі `@media` для розмірів не потрібні.
- На в'юпорті ≥ 1440×1024 `k = 1`, тобто рівно як у Figma. На більших екранах блок не збільшується: лишається 583 px, навколо чорний простір.
- Поля ≥ 16 px з усіх боків. Блок ніколи не ширший за `100vw − 32px` (немає горизонтального скролу) і не вищий за `100dvh − 32px` (множник 1.69 трохи менший за 583 / 340 ≈ 1.715, тож блок завжди вміщається по висоті; немає вертикального скролу).
- Мінімальна ціль дотику: на 320 px кнопки ≥ 44 px заввишки (≈ 49.4). Дві колонки вміщаються в один ряд навіть на 320 px, підписи й іконки не обрізаються (група `Reset` + іконка ≈ 146·k ≈ 72 px у колонці ≈ 139 px).
- Висота блока однакова в усіх станах (≈ 340·k): кнопки однієї висоти в обох розкладках, рядок цифр має фіксовану висоту (`line-height`).
- Налаштування розміру шрифту браузера на розкладку не впливають (розмір задає лише в'юпорт). Зум 200% / 400% працює без горизонтального скролу: CSS-в'юпорт стає меншим, `W` зменшується.
- Сенсорні екрани (`@media (hover: none)`): підпис і іконка білі за замовчуванням, hover-стану немає (див. «Візуальний стиль → Стани кнопок»).
- `touch-action: manipulation` на кнопках.
- `<meta name="viewport" content="width=device-width, initial-scale=1">` без `user-scalable=no` і `maximum-scale`.
- Тестові в'юпорти: 320×568, 375×667, 390×844, 768×1024, 1280×800, 1440×1024 (Figma), 1920×1080, а також landscape 568×320 і 844×390. Горизонтального й вертикального скролу немає ніде.
- Фон на весь в'юпорт за будь-якої орієнтації; при resize / зміні орієнтації канвас і радіус сліду (від меншої сторони) перераховуються.

Орієнтири (розрахунок за формулою вище). Підпис ≥ 24 px (великий текст) — від в'юпорта шириною ≈ 350 px (k ≥ 0.545), див. «Доступність → Контраст»:

| В'юпорт | W | k | Цифри | Підпис | Висота кнопки | Висота блока |
|---|---|---|---|---|---|---|
| 320×568 | 288 | 0.494 | ≈ 105.6 px | ≈ 21.7 px | ≈ 49.4 px | ≈ 168 px |
| 375×667 | 343 | 0.588 | ≈ 125.7 px | ≈ 25.9 px | ≈ 58.8 px | ≈ 200 px |
| 568×320 (landscape) | ≈ 486.7 | 0.835 | ≈ 178.4 px | ≈ 36.7 px | ≈ 83.5 px | ≈ 283.8 px (≤ 288) |

## Edge cases
- **Reset під час running**: одразу idle, `00:00`, відлік зупинено; «запізнілий» тік не повертає старе значення.
- **Подвійний Start** (дабл-клік, дабл-тап, утримання Enter): рівно один старт і жодної паузи на `00:00`. Після Start на тому ж місці з'являється Stop, тож друга дія в межах ≈ 400 мс ігнорується, а повтори keydown (`event.repeat`) не активують кнопку. Другий інтервал не створюється, `startedAt` не перезаписується, час не скидається і не прискорюється. Guard від повторного Start у reducer'і лишається, тож захист спрацює, навіть якщо два кліки прийдуть до ререндеру. Ефект з інтервалом має cleanup, тому StrictMode у dev не дає подвійного тіку.
- **Подвійний клік по Reset**: Reset зникає, Start розтягується на всю ширину й може опинитися під курсором. Друга дія в межах ≈ 400 мс ігнорується, тож таймер сам не стартує.
- **Клік у момент автостопу на ліміті**: слот Start/Stop зникає, і Reset стає єдиною кнопкою на всю ширину. Вікно ≈ 400 мс діє й після автостопу, тож клік, націлений на Stop, не скине таймер.
- **Натискання під час перетікання**: дія в межах вікна ≈ 400 мс ігнорується; натискання нічого не масштабує і не зсуває кнопку.
- **Stop → Start**: продовжує з того ж значення, включно з дробовою частиною секунди. Якщо Stop натиснуто через 400–1000 мс після старту, буде paused з `00:00` і кнопками Start · Reset.
- **Фонова чи згорнута вкладка**: браузер пригальмовує таймери (throttling), але після повернення значення одразу правильне, без «доганяння». За потреби перераховувати на `visibilitychange`. Шейдер фону у прихованій вкладці на паузі.
- **Сон ОС** під час running: час сну зараховується.
- **Системний годинник переведено назад**: `elapsed` не стає від'ємним.
- **Після 59:59**: лічба не продовжується. На `59:59` автостоп: paused, на екрані лише Reset на всю ширину; `60:00` і більше ніколи не показується. Якщо ліміт минув, поки вкладка була у фоні, після повернення буде `59:59` у paused. (Рішення 1.)
- **Перезавантаження або вивантаження вкладки**: idle `00:00` (збереження стану поза скоупом).
- **Немає WebGL** (контекст не створено, втрачено або шейдер не скомпілювався): фон чисто чорний, таймер працює як завжди, у консолі без помилок.
- **Немає `backdrop-filter`** або ввімкнено `prefers-reduced-transparency`: щільна заливка кнопок без розмиття. **`prefers-reduced-motion`**: фон чорний (ефект вимкнено), перетікання кнопок і переходи кольору вмісту миттєві.
- **Тач-пристрій / курсора немає**: у спокої фон чорний; слід з'являється лише за пальцем, що веде по екрану (`pointermove`), і зникає за ≈ 1.7 с. Hover-стану кнопок немає (`@media (hover: hover)`), підпис і іконка білі за замовчуванням.
- **Курсор поза вікном**: нових точок сліду немає, слід догасає за ≈ 1.7 с, екран стає чорним; повернення курсора починає нову лінію без відрізка від старої позиції.
- **Нерухомий курсор**: слід не оновлюється й зникає за ≈ 1.7–1.8 с; під курсором нічого не лишається.
- **Вузький в'юпорт (< ≈ 350 px) на hover-пристрої**: сірий підпис за замовчуванням < 24 px, контраст нижче порога великого тексту — прийняте відхилення (див. «Доступність → Контраст»).
- **Дуже низький в'юпорт** (landscape 568×320): блок масштабується за висотою (k ≈ 0.835) і вміщається без вертикального скролу.
- **Великий екран** (1920×1080 і більше): блок лишається 583 px, не збільшується.
- **Шрифт ще не завантажено** (Fontsource ставить `font-display: swap`): розкладка не ламається (висоти задані числами, горизонтального скролу немає), після завантаження блок не стрибає по висоті.
- **Зум браузера 200% / 400%** і зміна розміру шрифту в налаштуваннях: горизонтального скролу немає, вміст не обрізається.
- Довгий текст, мережа, порожні дані, списки тут не застосовні.

## Доступність
- Кнопки — нативні `<button type="button">` з видимим текстом `Start` / `Stop` / `Reset`; accessible name = лише текст. Іконки декоративні: `aria-hidden="true"`, `focusable="false"`, без `<title>`, `aria-label` і ролей, тож у імені кнопки їх немає. Фон і канвас мають `aria-hidden="true"`.
- Неактивних кнопок немає: показуються лише доступні дії, тож `disabled` і `aria-disabled` не використовуємо.
- Керування фокусом (фокус ніколи не падає на `body`):
  - Start ↔ Stop: фокус лишається на тому самому елементі слота;
  - Reset → idle: Reset зникає; якщо фокус був на Reset, він переходить на Start;
  - автостоп на ліміті: слот Start/Stop зникає; якщо фокус був на ньому, він переходить на Reset;
  - якщо фокус не на кнопках таймера, його ніхто не чіпає (автопереходи не крадуть фокус).
- Фокус: `:focus-visible` → `outline: 2px solid #fff` + `outline-offset: 3px` (рішення LEAD); підпис і іконка при цьому білі (1.0). Контраст ≥ 3:1 до фону навколо, зокрема над найсвітлішою точкою шейдера. Саме `outline`, а не `box-shadow`, бо його видно в forced-colors. Кільце не обрізається: у предках кнопок немає `overflow: hidden`, зокрема й під час перетікання. `outline: none` без заміни заборонено.
- Дисплей НЕ є live-регіоном (без `aria-live` і live-ролей), тож кожна секунда не озвучується. Скрінрідер може прочитати його звичайною навігацією.
- Live-регіон: візуально прихований `<p role="status">`. Він є в DOM з першого рендера (порожній), а текст змінюється тільки на переходах:

| Перехід | Текст |
|---|---|
| → running | `Timer running` |
| → paused (кнопка Stop) | `Timer stopped at 05:23` (поточне значення) |
| → idle (Reset) | `Timer reset` |
| → paused на ліміті | `Maximum time reached. Timer stopped at 59:59` |

- Сторінка: `<main>`, `<h1>Timer</h1>` (єдиний заголовок сторінки, лише для скрінрідерів: візуально прихований класом `.visually-hidden`, у дереві доступності лишається), `lang="en"`, `<title>Timer</title>`.
- `.visually-hidden` — стандартний патерн (допустимий еквівалент): `position: absolute; width: 1px; height: 1px; margin: -1px; padding: 0; border: 0; overflow: hidden; clip-path: inset(50%); white-space: nowrap`. Елемент поза потоком, тож не додає відступу чи `gap` над цифрами. Не `display: none`, не `visibility: hidden`, не атрибут `hidden` і не `aria-hidden` на `h1`: вони прибирають його з дерева доступності.
- Контраст (WCAG 2.2 AA) міряється на фактичних кольорах (піпеткою зі скріншота) з урахуванням заливки кнопок 20% і зерна; для білого тексту точка виміру — найсвітліша точка фону в будь-який момент анімації. Прийняте рішення (Рішення 10):
  - білий підпис (hover / focus-visible / active, а на сенсорних екранах завжди) і цифри ≥ 4.5:1 (для цифр це суворіше за 3:1, які WCAG вимагає для великого тексту); focus ring ≥ 3:1;
  - сірий підпис за замовчуванням (білий @ 0.4) на заливці кнопки ≈ 3.85:1 (заливка над чорним) — проходить AA для великого тексту (≥ 3:1), коли підпис ≥ 24 px, тобто на в'юпортах шириною ≥ ≈ 350 px. На вужчих в'юпортах із наведенням підпис < 24 px: це свідомо прийняте відхилення (на сенсорних підпис білий);
  - іконки декоративні, дублюють підпис: контраст не нормується;
  - сірий підпис над найсвітлішою ділянкою сліду не нормується (Відкрите питання 4).

  Розрахунки й обмеження яскравості фону — «Анімований фон → Яскравість».
- Сенсорні екрани: підпис і іконка білі за замовчуванням (`@media (hover: none)`, рішення користувача).
- Стан не передається кольором: усі кнопки однакові, стан читається за підписами кнопок і значенням. Для скрінрідерів — оголошення з таблиці вище.
- Враховуються налаштування користувача: `prefers-reduced-motion` (фон вимкнено, переходи миттєві), `prefers-reduced-transparency`, `forced-colors` (текст, іконки, кнопки і focus ring видимі).
- Зум 200% / 400% на десктопі не дає горизонтального скролу й не обрізає вміст.

- теми й перемикач теми (зокрема світла тема), налаштування;
- звуки, вібрація, нотифікації;
- countdown, введення тривалості, пресети;
- збереження стану (localStorage, URL), відновлення після перезавантаження;
- кола (laps), спліти, історія;
- мілісекунди / десяті, години (`h:mm:ss`);
- гарячі клавіші;
- час у `document.title`, динамічний favicon;
- кілька таймерів, роутинг, бекенд, PWA/офлайн, аналітика, i18n;
- Storybook.

## Критерії приймання

### Логіка
1. Після завантаження стан idle: `00:00` і одна кнопка `Start`.
2. У кожному стані набір кнопок і їхні підписи точно відповідають таблиці «Що на екрані»: idle — лише `Start` (на всю ширину); running — `Stop` · `Reset`; paused — `Start` · `Reset`; ліміт — лише `Reset` (на всю ширину). Усі кнопки в одному стилі, без акценту. Неактивних кнопок і `aria-disabled` немає.
3. Після Start через ~1 с з'являється `00:01`, далі +1 щосекунди, без пропусків і «зависань» (у видимій вкладці).
4. Stop фіксує значення. Start після Stop продовжує з показаного значення, без скидання і без стрибка.
5. Reset у running і в paused одразу дає `00:00` і idle, відлік зупинено; старе значення не «блимає».
6. Дабл-клік / дабл-тап / утримання Enter на Start дають рівно один старт, без паузи на `00:00`: за 10 с реального часу дисплей додає 10 с (±1 с). Дабл-клік по Reset не запускає таймер. У коді є вікно ≈ 400 мс після переходу (одна константа), ігнорування `event.repeat`, guard від повторного старту в reducer'і; інтервал створюється в одному місці, ефект має cleanup.
7. Точність: після 5 хв running розбіжність з еталонним секундоміром ≤ 1 с (або перевірка коду: значення обчислюється з `Date.now()`, а не з лічильника тіків).
8. Фон: running → інша вкладка на ≥ 60 с → повернення: значення одразу правильне (±1 с).
9. 10 циклів Start/Stop поспіль: показаний час дорівнює сумарному реальному часу в running (±1 с).
10. Формат завжди `mm:ss` з ведучими нулями (`00:07`, `01:00`, `10:00`).
11. Ліміт (Рішення 1): на `59:59` автостоп: paused, на екрані лише `Reset` (на всю ширину). `60:00` і більше не з'являється ніколи, зокрема після повернення з фонової вкладки. Ліміт задано однією константою (`3_599_000` мс). Перевірка: юніт-тест `formatTime`/reducer або тимчасово зменшена константа.

### Адаптив
12. На всіх тестових в'юпортах (див. «Адаптивність») немає ні горизонтального, ні вертикального скролу, час стоїть в одному рядку, блок видно повністю, підписи й іконки кнопок не обрізані.
13. Ширина дисплея не змінюється зі зміною цифр (напр. `01:11` → `01:12`).
14. Масштабування (рішення LEAD): ширина блока `W = min(583px, 100vw − 32px, (100dvh − 32px) × 1.69)`, усі розміри пропорційні `k = W / 583` (крім `blur(4px)`, обідка 1 px і outline фокуса: вони фіксовані).
    - на ≥ 1440×1024 `k = 1` (рівно Figma); на 1920×1080 блок лишається 583 px;
    - на 320×568 кнопки ≥ 44 px заввишки (≈ 49.4), дві колонки в одному ряду, підписи й іконки не обрізані;
    - landscape 568×320 без вертикального скролу (блок ≈ 283.8 ≤ 288 px);
    - висота блока однакова в усіх станах (див. 32);
    - розміри не залежать від налаштування розміру шрифту браузера.
15. Viewport meta не блокує зум; зум 200% на 1280 px і 400% не дають горизонтального скролу.

### Візуальний стиль (Figma) і фон
16. Відповідність Figma на 1440×1024 в idle, running і paused, допуск ±1.5 px (DevTools: computed styles і розміри боксів; за наявності Figma — накладання на `Desktop - 1` / `Desktop - 2` / `Desktop - 3`):
    - сторінка `#000`; картки, панелі й рамки блока немає;
    - блок: 583 × ≈ 340 у всіх станах; центр блока = центр в'юпорта (±1.5 px по обох осях);
    - цифри: IBM Plex Sans 600, 213.69 px, line-height 101% (≈ 215.8), letter-spacing 0.2%, `#FFF`; рядок цифр 583 × ≈ 216; ширина `00:00` ≈ 583 ± 3;
    - gap цифри → кнопки 24; висота ряду кнопок 100;
    - кнопки: висота 100, `border-radius` 23 px, заливка `rgba(107, 107, 107, 0.2)`, без `border`, `backdrop-filter: blur(4px)`;
    - розкладка: idle — одна кнопка 583; running і paused — дві кнопки ≈ 281.5 з gap 20 (ряд 583); ліміт — одна `Reset` 583;
    - підпис: IBM Plex Sans 400, 44 px, line-height 101%, letter-spacing −2%; іконка — inline SVG, рамка 32 × 40 (play / pause / reset), після підпису; gap підпис → іконка: Start 6, Stop 4, Reset 4;
    - позиції підпису й іконки в кнопці — за таблицею «Візуальний стиль → Вміст кнопки» (±1.5 px) у idle, running і paused;
    - paused: підпис Start починається там само, де підпис Stop (x ≈ 78 ± 1.5); при Stop ↔ Start текст не стрибає;
    - візуально збігається з Figma: матова заливка, світлий обідок кнопок, цифри без градієнта й відблиску.
17. Шрифт — лише IBM Plex Sans через `@fontsource/ibm-plex-sans`, імпортовано тільки latin 400 і 600; у Network лише ці два woff2 (self-hosted, запитів до Google Fonts немає). Inter Variable і Aeonik відсутні в проєкті (`package.json`, `src`, `index.html`, файли шрифтів). Цифри — 600, підписи кнопок — 400. Фолбек `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`.
18. Кнопки, стани, обідок і перетікання:
    - усі кнопки однакові: одна заливка й геометрія, без акценту; вміст — підпис + іконка праворуч;
    - кольори вмісту: default — підпис білий @ 0.4, іконка білий @ 0.3; `:hover` (лише `@media (hover: hover)`), `:focus-visible` і `:active` — обидва 1.0, transition 150 мс (reduced-motion — без transition); на сенсорних екранах (`@media (hover: none)`) — обидва 1.0 за замовчуванням. Перевірка: DevTools (computed color / opacity) у кожному стані, емуляція touch для `hover: none`;
    - заливка: default 20% → hover ≈ 28% (лише `@media (hover: hover)`) → active ≈ 16%; без scale при натисканні; transition заливки ≤ 150 мс; focus-visible — `outline: 2px solid #fff` з `outline-offset: 3px`;
    - обідок скла: світла лінія 1 px по контуру, яскравіша у верхньо-лівому й нижньо-правому кутах (два inset `box-shadow` ≈ білий 0.22 і 0.17); на hover / active / focus не змінюється; у `forced-colors` його немає;
    - перетікання 1 ↔ 2: тривалість 250 мс, крива `cubic-bezier(0.4, 0, 0.4, 1)` (м'який розгін і м'яка посадка: без різкого старту, без overshoot); у keyframes і transitions лише `transform` / `opacity`, єдиний виняток — колір обідка; цифри й висота блока не рухаються; перший і останній кадри збігаються зі статичними розкладками;
    - основна кнопка змінює ширину через scale по X, а вміст не розтягується: ширина підпису й іконки в будь-якому кадрі відхиляється від статичної не більше ніж на 1% (перевірка: `getBoundingClientRect().width` підпису й іконки в кількох кадрах, напр. пауза `document.getAnimations()` на одному `currentTime`);
    - `Reset` з'являється на своєму місці: `opacity` 0 → 1 за ≈ 190 мс із затримкою ≈ 50 мс, зсув ≤ 8 px з боку основної кнопки, без scale; зникає: `opacity` 1 → 0 за ≈ 120 мс, зсув ≤ 6 px;
    - обідок основної кнопки під час перетікання: плавно гасне за перші ≈ 20% часу, прихований до ≈ 50%, плавно повертається до 100%, без миттєвих вимикань;
    - `BUTTON_MOTION_MS` (стан анімації в React) = 280 мс, тобто менше за вікно 400 мс;
    - кнопка, що зникає, неінтерактивна одразу (`inert` чи еквівалент);
    - `prefers-reduced-motion` → перетікання й переходи кольору вмісту миттєві;
    - Performance (4× CPU slowdown): перетікання й hover не дають Layout на кожен кадр.
19. Фон — вигляд і рух (скріншоти / запис екрана: спокій; вказівник рухається по діагоналі й по колу ≥ 4 с; зупинка; емуляція тачу):
    - у спокої (після завантаження і через ≈ 1.8 с після зупинки вказівника) фон чисто чорний `#000`, без плям і віньєток;
    - при русі вказівника (mouse / pen / дотик) за ним лишається широкий м'який слід: гаусів профіль без ядра й різкого краю, радіус біля вказівника ≈ 11% меншої сторони (≈ 225 px завширшки на півяскравості при 1440×1024), з віком ширшає до ≈ ×2.3 і блідне, пікова непрозорість ≈ 70%, зерно ≈ ±3.5%;
    - після зупинки слід зникає повністю за ≈ 1.7–1.8 с (кадри на 0 / 0.9 / 1.8 с); постійної «голови» під нерухомим вказівником немає;
    - у сліду видно три кольори циклу: синій `#2438C8` → фіолетовий `#6B35C8` → смарагдовий `#12936F` → синій, період ≈ 3.6 с, сусідні кольори одночасно; старіючи, слід темнішає: синій / фіолетовий → `#24476B`, смарагдовий → `#17505A`, далі `#141B4D` → прозоре; теплих, рожевих і білих відблисків немає;
    - швидкий рух лишає суцільну лінію (без «намистин»); вхід вказівника з іншого місця (вихід за вікно й повернення, новий дотик) не тягне лінію від старої позиції;
    - фон не залежить від стану таймера. Яскравість — див. 26.
20. Фон — легкий:
    - один `<canvas>` (WebGL1), один rAF-цикл, один draw на кадр; без текстур, framebuffer'ів і post-process; бібліотек немає (див. 30);
    - внутрішня роздільність ≈ 0.5× CSS-розміру, DPR не множиться (перевірити `canvas.width`);
    - rAF працює лише поки слід живий: у спокої 0 кадрів (Performance: за ≥ 2 с без руху немає Animation Frame Fired); у прихованій вкладці rAF не крутиться;
    - Performance з 4× CPU slowdown при русі вказівника: FPS ≳ 50, без Long Tasks від фону, без Layout/Paint на кожен кадр. Paint flashing: нічого, окрім канваса, не підсвічується (раз на секунду — лише цифри; під час перетікань — кнопки);
    - у кадрі немає читання layout і змін DOM/стилів; `pointermove` лише записує координати;
    - ефект має cleanup: у dev із StrictMode лишається один канвас, один rAF-цикл і один набір слухачів.
21. Фолбеки:
    - без WebGL (емуляція: вимкнений WebGL, заглушка `getContext`, `WEBGL_lose_context`): канваса немає, фон чисто чорний, інтерфейс працює, у консолі без помилок;
    - `prefers-reduced-motion: reduce` (емуляція в DevTools): ефект вимкнено — канваса немає, фон чорний, `pointermove` нічого не малює, rAF не крутиться; перемикання емуляції «на льоту» вмикає й вимикає ефект; перетікання кнопок і переходи кольору вмісту миттєві;
    - без `backdrop-filter` (`@supports not`) і з `prefers-reduced-transparency: reduce`: заливка кнопок щільна ≈ `#151515`–`#1C1C1C`, без розмиття; білий текст ≥ 4.5:1;
    - `forced-colors` — див. 29.
22. Фон під контентом і не перехоплює кліки, фокус і виділення (`pointer-events: none`, `aria-hidden="true"`); не додає скролу; при overscroll на мобільному не видно білого (`html`/`body` `#000`, `color-scheme: dark`).

### Доступність
23. Tab ходить лише по видимих кнопках у порядку основна → Reset; Enter і Space активують; focus ring — `outline: 2px solid #fff` з `outline-offset: 3px`, видимий над найсвітлішою точкою фону (≥ 3:1) і не обрізається (немає `overflow: hidden` у предках кнопок, зокрема під час перетікання).
24. Фокус ніколи не падає на `body`. При Start ↔ Stop він лишається на тому самому елементі (слот не перемонтовується). Після Reset фокус переходить на Start, якщо був на Reset. На автостопі на ліміті фокус переходить на Reset, якщо був на слоті. Якщо фокус не на кнопках таймера, автопереходи його не чіпають.
25. Посекундно нічого не озвучується (дисплей без `aria-live`). На кожен перехід звучить рівно одне оголошення з таблиці в «Доступності»: `Timer running`, `Timer stopped at mm:ss`, `Timer reset`, `Maximum time reached. Timer stopped at 59:59` (перевірка через VoiceOver або код).
26. Контраст на фактичних кольорах — піпеткою зі скріншота, з урахуванням заливки кнопок 20% і зерна (прийняте рішення, Рішення 10). Для білого тексту перевірити статичний кадр і ≥ 3 моменти анімації, зокрема коли слід під цифрами й під кнопками (вказівник над ними), у default / hover / active; точка виміру — найсвітліша точка фону:
    - білий підпис (hover / focus-visible / active; на сенсорних екранах і за замовчуванням) ≥ 4.5:1;
    - цифри ≥ 4.5:1;
    - focus ring ≥ 3:1;
    - сірий підпис за замовчуванням (білий @ 0.4) міряти на заливці над чорним (спокій): ≈ 3.85:1, тобто ≥ 3:1 (AA для великого тексту) за підпису ≥ 24 px (в'юпорт ≥ ≈ 350 px); на вужчих в'юпортах із наведенням підпис < 24 px — прийняте відхилення; над слідом вимоги немає (Відкрите питання 4);
    - іконки декоративні: контраст не міряється.
27. Стан не передається кольором (є текст кнопок і значення дисплея). Фон і канвас мають `aria-hidden="true"`; іконки декоративні (`aria-hidden="true"`, `focusable="false"`), ім'я кнопки — лише текст (DevTools → Accessibility: name `Start` / `Stop` / `Reset`).
28. Є `<main>` і `<h1>Timer</h1>`: візуально прихований (`.visually-hidden`), але доступний у дереві доступності (DevTools → Accessibility: heading, level 1, name «Timer»; без `display: none`, `visibility: hidden`, `hidden`, `aria-hidden`). Також `lang="en"`, `<title>Timer</title>`.
29. В емуляції forced colors (DevTools) текст, іконки, кнопки (видима рамка) і focus ring видимі; підпис і іконка в системних кольорах без прозорості; обідка скла немає; фон-канвас прихований.

### Скоуп і якість
30. Нічого з «Поза скоупом» не реалізовано; залишків шаблону Vite немає; runtime-залежності — тільки `react`, `react-dom`, `@fontsource/ibm-plex-sans` (шрифт self-hosted, запитів до Google Fonts немає). Бібліотек для WebGL / шейдерів / анімацій / іконок і файлів-зображень для фону й іконок немає: іконки — inline SVG.
31. `npm run build` (разом із `tsc`) проходить без помилок; у консолі немає помилок і warnings.

### Контекстні кнопки (2026-10-02)
32. Блок не змінює висоту при переходах між станами (на всіх в'юпортах): ряд з однією і з двома кнопками однаково високий, цифри не зсуваються.

### Без видимого заголовка (2026-10-02)
33. На сторінці немає видимого слова «Timer»: верхній елемент блока — цифри. Окремих відступів над цифрами не задано: розкладку дає Figma й центрування блока (Рішення 9). `h1` лишається в DOM (див. 28).

### Композиція (2026-10-05, замість композиції Dribbble)
34. На 1440×1024 і 1280×800 композиція як у Figma: блок по центру обох осей (±1.5 px), навколо чорний простір, нічого не обрізано (зокрема focus ring), скролу немає. На 1920×1080 блок лишається 583 px. Слід диму не робить цифри й білі підписи нечитабельними (див. 26). Перевірити кілька кадрів анімації та статичні стани (чорний спокій, reduced-motion).

## Рішення
Рішення 1–8 затверджено користувачем (2, 4, 7 і 8 скасовано або звужено Рішенням 9). Рішення 9 — запит користувача (Figma, ефект фону) плюс пункти «Рішення LEAD» і «Уточнення spec-агента», які користувач окремо не затверджував; частини Рішення 9 скасовано Рішенням 10. Рішення 10 — фінальний дизайн: значення з Figma зчитано LEAD'ом; сенсорне рішення — користувача; контраст сірого підпису — прийняте рішення. Рішення 11 — запит користувача («заспокой» перетікання кнопок), результат ним схвалено; уточнює Рішення 9 і 10 лише в частині руху перетікання й обідка під час нього.
1. **Ліміт — зупинка на `59:59`.** Константа `3_599_000` мс. На `59:59` автостоп: paused, на екрані лише Reset (на всю ширину); оголошення `Maximum time reached. Timer stopped at 59:59`. `60:00` і більше ніколи не показується.
2. **Шрифт — замінено Рішенням 9** (раніше був Inter Variable; тепер IBM Plex Sans, 400 і 600). `font-variant-numeric: tabular-nums` для цифр лишається.
3. **Progress-смугу й кільце прогресу не додаємо**, зокрема кільце з референсу Apple Watch. Вони лишаються в «Поза скоупом».
4. **Рестайл (2026-10-02) — скасовано Рішенням 9 повністю** (референси Apple Watch і Dribbble «Leflow Focus Timer Website» більше не використовуються; акцент, форма кнопок, рядок стану й шрифт — див. 9). У силі лишилось лише: темний фон (тепер чорний) і відсутність кільця прогресу (3).
5. **Контекстні кнопки замість неактивних (2026-10-02).** На екрані лише доступні дії: idle — `Start`; running — `Stop` · `Reset`; paused — `Start` · `Reset`; ліміт — `Reset`. `Start` і `Stop` — один і той самий `<button>`. Неактивні (приглушені) кнопки й `aria-disabled` не використовуються. Підпис кнопки зупинки з ТЗ замінено на `Stop` Рішенням 9.
6. **Без видимого заголовка (2026-10-02): `h1` лише для скрінрідерів.** Користувач: «прибери слово таймер». `<h1>Timer</h1>` лишається в DOM як заголовок сторінки, але візуально прихований (`.visually-hidden`); видимого слова «Timer» немає, верхній елемент блока — цифри. `<title>Timer</title>` і `lang="en"` без змін. Висота блока однакова в усіх станах (критерій 32 у силі).
7. **Більший відступ над цифрами (2026-10-03) — скасовано Рішенням 9:** картки немає, відступів картки немає; розкладку блока задає Figma.
8. **iOS 26 Liquid Glass (2026-10-03) — скасовано Рішенням 9 повністю** (перелік — у 9). У силі лишається лише те, що shot-режиму й експорту PNG немає (див. «Поза скоупом»).
9. **Дизайн із Figma (2026-10-05).** Користувач: «розроби цей дизайн + додай такий ефект [як hero shaders.com] в синьо-зеленому кольорі, легкий, не важкий, по руху курсору».     - **Димний слід із трьома кольорами.** Фон чорний; за рухомим вказівником лишається слід ≈ 1.7 с (синій → фіолетовий → смарагдовий, період ≈ 3.6 с; старіючи, темнішає й блідне). Скасовує з Рішення 9: синьо-зелену «димну» пляму, що йде за курсором з інерцією й завихренням; автономний дрейф без курсора; обмеження яскравості піку старої палітри (замінено піковою непрозорістю ≈ 70%); CSS-фолбек (CSS-пляма без WebGL); статичний кадр при reduced-motion (тепер ефект вимкнено, фон чорний).
    - **Контраст (прийняте рішення).** Сірий підпис @ 0.4 на заливці кнопки ≈ 3.85:1 — проходить AA для великого тексту (підпис ≥ 24 px, тобто в'юпорти ≥ ≈ 350 px); на вужчих в'юпортах із наведенням підпис < 24 px — свідомо прийняте відхилення (на сенсорних підпис білий). Білий підпис (hover / focus / touch) і цифри ≥ 4.5:1 у найсвітлішій точці фону. Іконки декоративні: контраст не нормується.
    - **Без змін:** логіка, стани, таблиця переходів, модель часу, ліміт 59:59, контекстні кнопки, вікно 400 мс, правила фокусу, `inert`, прихований `h1`, live-регіон з текстами `Timer stopped at …`. Нумерацію критеріїв приймання 1–34 збережено (змінено зміст 12, 14, 16, 18–21, 26, 27, 29, 30, 34).
11. **Спокійніше перетікання кнопок (2026-10-05).** Користувач: «анімація при кліку на Start занадто активна, заспокой»; результат схвалено. Змінюється лише рух перетікання 1 ↔ 2 і обідок під час нього; розкладки, логіка, вікно 400 мс, `inert` і правила фокусу — без змін.
    - **Тривалість і крива.** Було ≈ 240–250 мс і приклад кривої `cubic-bezier(0.2, 0, 0, 1)` або `ease-out` (різкий старт). Стало 250 мс і `cubic-bezier(0.4, 0, 0.4, 1)`: м'який розгін і м'яка посадка, без різкого старту й overshoot.
    - **Ширина через scale з контр-scale вмісту.** Кнопка, що лишається (основна; на ліміті — `Reset`), змінює ширину через scale по X; підпис і іконка в кожному кадрі отримують точний контр-scale, тож не розтягуються: відхилення ширини ≤ 1% у будь-якому кадрі.
    - **`Reset` більше не виїжджає з-під основної кнопки.** Було: кнопка, що з'являється, виїжджала з-під основної. Стало: з'являється на своєму місці — `opacity` 0 → 1 за ≈ 190 мс із затримкою ≈ 50 мс, зсув ≤ 8 px з боку основної кнопки, без scale. Зникнення: `opacity` 1 → 0 за ≈ 120 мс, зсув ≤ 6 px; кнопка, що зникає, одразу `inert`.
    - **Обідок скла під час перетікання.** Було: прихований на першій половині анімації. Стало: плавно гасне за перші ≈ 20% часу, прихований до ≈ 50%, плавно повертається до 100%, без миттєвих вимикань.
    - **`BUTTON_MOTION_MS` = 280 мс** (тривалість стану анімації в React): трохи довше за рух, менше за вікно 400 мс.
    - **Без змін:** у keyframes лише `transform` / `opacity` (виняток — колір обідка), `prefers-reduced-motion` → миттєво, висота блока й статичні позиції. Нумерацію критеріїв приймання 1–34 збережено (змінено зміст 18).

## Відкриті питання
Блокуючих немає: builder може починати, reviewer — приймати за критеріями. Нижче — розбіжності й припущення; діє дефолт, якщо LEAD чи користувач не змінять.
1. **Закрито Рішенням 10.** Ряд кнопок у running: у фінальному Figma він 583 px (2 × ≈ 281.5 + gap 20), як і в SPEC; розбіжності з макетом (580 px зі зсувом 3 px) більше немає.
2. **Яку саме сцену hero на shaders.com мав на увазі користувач?** Сторінку не аналізували: ефект (димний слід курсора) описано в «Анімований фон» як рішення LEAD за референсом. Дефолт — як описано.
3. **Видимий рядок стану** (назва поточного стану на екрані) прибрано: у Figma його нема (блок = цифри + кнопки, в усіх трьох кадрах). Дефолт — без нього. Якщо його треба повернути, потрібен макет.
4. **Сірий підпис над найсвітлішою ділянкою сліду.** Прийняте рішення дає ≈ 3.85:1 для сірого підпису (білий @ 0.4) на заливці кнопки над чорним. Коли під кнопкою без hover проходить найяскравіша частина сліду, підпис блідне відносно заливки: оцінка spec-агента ≈ 2.4:1 під піком смарагдового й ≈ 2.9:1 під піком фіолетового (заливка 20%, фон ≈ 70% кольору). Ділянка сліду живе ≈ 1.7 с; під вказівником кнопка вже біла (hover), на сенсорних підпис білий завжди. Дефолт: критерій 26 міряє сірий підпис над чорним (спокій), над слідом вимоги немає. Якщо потрібно ≥ 3:1 і там, треба підняти альфу сірого підпису або знизити пікову непрозорість сліду; це змінює дизайн, тож рішення за LEAD / користувачем.
