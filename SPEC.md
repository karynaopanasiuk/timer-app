# Timer

Тип: застосунок/сторінка (Vite + React + TypeScript; не Storybook)

Джерело:
- ТЗ користувача (дослівно): «один екран: великий час mm:ss по центру · кнопки Start / Pause / Reset · стани: idle (00:00) → running → paused · адаптив (норм виглядає на телефоні), чисто, без зайвого функціоналу».
- Доповнення користувача (2026-10-02): спочатку на екрані лише Start, а після старту з'являються Pause і Reset — контекстні кнопки (Рішення 5).
- Стиль (рестайл 2026-10-02, Рішення 4): референс — Apple Watch focus-таймер (скрін від LEAD) + https://dribbble.com/shots/26132755-Leflow-Focus-Timer-Website (сторінка не віддала контент, тому аналіз зроблено зі скріна). Попередній референс (Risk Dashboard Cards) більше не актуальний. Figma немає, отже всі візуальні значення нижче — оцінки зі скріна (≈).
- Коли ТЗ і референс розходяться, перемагає ТЗ. Приклад: на референсі є помаранчеве кільце прогресу і тривалість `25 MIN`, а за ТЗ потрібні лише час і кнопки Start / Pause / Reset, тож кільця немає (Рішення 3).

## Мета
Мінімалістичний таймер на один екран. Рахує вгору від `00:00` і показує минулий час `mm:ss` на скляній (glassmorphism) картці поверх повільного анімованого фону. Керування — Start / Pause / Reset; має добре виглядати й працювати від 320 px до десктопа.

## Екрани / частини
Один екран, без роутингу.

```
 ░░ фон: майже чорний + м'яка віньєтка + ледь помітні сірі/помаранчеві відблиски ░░
        ┌─────────────────────────────────────────┐
        │                  TIMER                  │  ← h1: тихий сірий капс-лейбл
        │                                         │
        │                 05:23                   │  ← тонкі білі цифри
        │                 RUNNING                 │  ← рядок стану: капс, тут помаранчевий
        │                                         │
        │   [   || Pause   ]  [   ↺ Reset    ]    │  ← running: Pause● (помаранчева) + Reset (glass)
        └─────────────────────────────────────────┘
   idle — лише Start● по центру · paused — Start● + Reset · ліміт — лише Reset● по центру
```

- `App` — `<main>` на всю висоту в'юпорта (`min-height: 100dvh`), картка по центру по обох осях.
- `Background` — декоративний шар (`aria-hidden="true"`), див. «Анімований фон».
- `Timer` — glass-картка, єдиний функціональний компонент, без обов'язкових props:
  - заголовок `<h1>Timer</h1>` — тихий сірий капс-лейбл;
  - дисплей `mm:ss`, завжди в один рядок;
  - рядок стану: капс-лейбл стану, сірий або помаранчевий (не live-регіон);
  - кнопки: слот основної дії (`Start` ↔ `Pause`, один і той самий `<button>`) і `Reset`; на екрані лише доступні дії (див. «Поведінка → Кнопки»);
  - візуально прихований live-регіон `role="status"` (див. «Доступність»);
  - логіка: reducer / хук `useTimer` з переходами з таблиці нижче (це джерело правди) + чиста функція `formatTime(ms) → "mm:ss"`.
- Іконки — inline SVG у коді, без icon-бібліотек.
- Мова UI англійська (лейбли взято з ТЗ): `<html lang="en">`, `<title>Timer</title>`.
- Runtime-залежності: `react`, `react-dom`, `@fontsource-variable/inter` (Рішення 2). Фон і анімація — чистий CSS. Залишки шаблону Vite (логотипи, counter, демо-стилі) прибрати.

## Стани

### Що на екрані
| Стан | Дисплей | Рядок стану | Кнопки (● — помаранчева, основна дія) |
|---|---|---|---|
| idle | `00:00` | `Idle`, сірий | `Start`● |
| running | минулий час, +1 щосекунди | `Running`, помаранчевий | `Pause`● · `Reset` (glass) |
| paused | застигле значення (може бути `00:00`, якщо Pause натиснуто через 400–1000 мс після старту) | `Paused`, сірий | `Start`● · `Reset` (glass) |
| paused на ліміті `59:59` ¹ | `59:59` | `Limit reached`, помаранчевий | `Reset`● (єдина кнопка) |

¹ Див. Рішення 1.

### Переходи: стан × кнопка → новий стан
| Стан \ кнопка | Start | Pause | Reset |
|---|---|---|---|
| idle | → running, відлік від 0 | — | — |
| running | — (не перезапускає, не скидає точку старту) | → paused, значення фіксується | → idle, `00:00`, відлік зупинено |
| paused | → running, продовжує з того ж значення | — | → idle, `00:00` |
| paused на ліміті | — | — | → idle, `00:00` |

`—`: такої кнопки на екрані немає, тож і дії немає; стан не змінюється. Якщо така дія все ж надійде (подвійний клік, гонка рендеру), reducer її ігнорує.
Автоматичний перехід: running → paused на ліміті, щойно минулий час досягає `59:59`.

### Стани кнопок
- default, hover (тільки `@media (hover: hover)`), active (натиснута), focus-visible. Як вони виглядають — див. «Візуальний стиль».
- Неактивних станів немає: дія, недоступна в поточному стані, просто не показується (див. «Поведінка → Кнопки»).
- loading / empty / error / success не застосовні: мережі й даних немає.

## Поведінка

### Модель часу (точність)
- Час береться з реального годинника, а не з підрахунку тіків:
  - `accumulatedMs` — накопичено за попередні запуски; `startedAt` — `Date.now()` на момент останнього Start або `null`;
  - `elapsed = accumulatedMs + (running ? Date.now() - startedAt : 0)`, знизу обмежено 0, зверху лімітом;
  - Start: `startedAt = now`. Pause: `accumulatedMs += now - startedAt; startedAt = null`. Reset: `accumulatedMs = 0; startedAt = null`.
- Джерело — саме `Date.now()`: він зараховує й час сну ОС, як фізичний секундомір. `performance.now()` у частині браузерів цей час не рахує.
- Інтервал/таймаут лише запускає перерахунок. Він працює тільки в running, активний завжди щонайбільше один, крок ≤ 250 мс (або `setTimeout` до наступної межі секунди). Так секунди міняються вчасно й без пропусків.
- Pause зберігає значення з точністю до мс, без округлення до секунд.
- Відображення: `s = floor(elapsed / 1000)`, `mm = floor(s / 60)`, `ss = s % 60`, обидва з ведучим нулем до 2 цифр. `00:01` з'являється через 1 с після Start.
- Ліміт задано однією константою (`59:59` = `3_599_000` мс). Коли його досягнуто, `elapsed` фіксується на ліміті, стан → paused. `60:00` і більше ніколи не показується.

### Кнопки
- На екрані лише доступні дії (колонка «Кнопки» в таблиці «Що на екрані»).
- Слот основної дії — один і той самий `<button>`: той самий DOM-елемент, React його не перемонтовує. Він змінює лейбл, іконку й дію: `Start` в idle і paused, `Pause` у running. Дві різні кнопки умовно не рендерити. На ліміті слот зникає.
- `Reset` — окрема кнопка. Вона з'являється в running і paused, на ліміті лишається єдиною (помаранчевою), в idle її немає.
- Порядок у DOM і візуально: основна → Reset.
- Захист від подвійних дій: після переходу під курсором чи пальцем може опинитися інша кнопка. Тому дії, що надходять протягом ≈ 400 мс після попереднього переходу, ігноруються (одна константа, напр. `ACTION_LOCK_MS = 400`). Вікно діє після переходів, ініційованих користувачем, і після автостопу на ліміті. При утриманні Enter повтори keydown (`event.repeat`) не активують кнопку (`preventDefault`). Guard від повторного Start у reducer'і лишається.
- Поява/зникнення: легкий fade/scale ≤ 200 мс тільки через `opacity`/`transform`; з `prefers-reduced-motion: reduce` — миттєво. Кнопка, що зникає, одразу стає неінтерактивною (не клікається, поза Tab-порядком). Після вікна ≈ 400 мс анімація не блокує кліки по новій кнопці.
- Фокус — див. «Доступність → Керування фокусом».

### Клавіатура
- Tab / Shift+Tab ходять лише по видимих кнопках: основна → Reset.
- Enter / Space активують кнопку під фокусом; повтори keydown при утриманні (`event.repeat`) ігноруються.
- Глобальних гарячих клавіш немає.

### Анімації
- Цифри й рядок стану змінюються миттєво, без flip/fade/блимання.
- Анімуються фон (див. «Анімований фон») і поява/зникнення кнопок (див. «Кнопки»).
- На кнопках допустимий transition кольору/фону ≤ 150 мс; `transform` — лише для появи/зникнення.

## Візуальний стиль
Темний чистий стиль за референсом Apple Watch focus-таймера: майже чорний фон, тонкі білі цифри, дрібні капс-лейбли, один помаранчевий акцент і темне скло. Значення орієнтовні (≈). Їх можна підкрутити, якщо критерії приймання виконуються.

- **Шрифт**: Inter Variable через `@fontsource-variable/inter` (Рішення 2): self-hosted, без запитів до Google Fonts. Фолбек `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`. Для цифр `font-variant-numeric: tabular-nums`.
- **Кольори**:
  - фон ≈ `#000`–`#0a0a0a`;
  - основний текст білий; вторинний (сірий) — білий ≈ 55–65%;
  - акцент ≈ `#FF9F0A` (Apple system orange, dark);
  - текст та іконки на акценті ≈ `#0a0a0a`. Білий на `#FF9F0A` дає ≈ 2:1 (FAIL), а `#0a0a0a` — ≈ 9.6:1.
- **Текст**:
  - заголовок `<h1>Timer</h1>` — тихий капс-лейбл, як `25 MIN` на референсі: ≈ 13–14 px, вага ≈ 500, letter-spacing ≈ 0.08–0.12em, `text-transform: uppercase`, сірий. Без іконки (щонайбільше дуже скромна сіра);
  - цифри — вага ≈ 300–400, білі, `line-height: 1` (розмір — в «Адаптивності»);
  - рядок стану — капс-лейбл, як `FOCUS`: ≈ 13–14 px, вага ≈ 500–600, letter-spacing ≈ 0.08–0.12em, uppercase лише через CSS; у DOM текст лишається `Idle` / `Running` / `Paused` / `Limit reached`. `Running` і `Limit reached` помаранчеві, `Idle` і `Paused` сірі. Кольорової крапки немає;
  - лейбли кнопок ≈ 15–16 px, вага ≈ 500–600.
- **Glass-картка** (темне скло):
  - фон: білий ≈ 4–7% на чорному; `backdrop-filter: blur(≈24px)` разом із `-webkit-backdrop-filter`;
  - border 1 px, білий ≈ 8–12%; за бажанням тонкий світлий хайлайт по верхньому краю (≈ `inset 0 1px 0 rgba(255, 255, 255, 0.06–0.1)`);
  - радіус ≈ 28 px; м'яка тінь ≈ `0 24px 60px rgba(0, 0, 0, 0.5)`;
  - на сторінці лише картка має `backdrop-filter`.
- **Кнопки**: прямокутні, радіус ≈ 12–14 px, висота ≥ 52 px. Дві кнопки — рівні колонки, одна — по центру (див. «Адаптивність»). Усередині іконка (inline SVG ≈ 18 px, `currentColor`) + текст. Іконки: Start — play, Pause — pause, Reset — rotate-ccw.
- **Основна дія — помаранчева** (● у таблиці «Що на екрані»: в idle і paused це Start, у running — Pause, на ліміті — Reset як єдина кнопка). Суцільна заливка ≈ `#FF9F0A`, лейбл та іконка ≈ `#0a0a0a`. Hover/active — трохи світліша/темніша, контраст ≥ 4.5:1 у всіх станах.
- **Glass-кнопка** — Reset поруч з основною дією (running, paused): білий ≈ 6–8%, border 1 px білий ≈ 10%, білий текст, без власного `backdrop-filter`. Hover: заливка світлішає на ≈ 4%. Active — трохи темніше.
- **Вирівнювання**: увесь вміст картки по центру (за ТЗ час по центру).
- `html`/`body`: фон ≈ `#000` і `color-scheme: dark`, щоб при overscroll/bounce на мобільному не проглядав білий.

## Анімований фон
- Фон власний, на чистому CSS. Жодних зображень чи ассетів із референсів (копірайт) і жодних зовнішніх ресурсів.
- Шар: `position: fixed; inset: 0`, під контентом; `overflow: hidden`, `pointer-events: none`, `aria-hidden="true"`. Відблиски, що виходять за край екрана, не додають скролу.
- Основа (статична): майже чорний ≈ `#000`–`#0a0a0a` з м'якою радіальною віньєткою, як на референсі: центр трохи світліший, ≈ `radial-gradient(ellipse at 50% 40%, #141414 0%, #0a0a0a 45%, #000 100%)`.
- Фон лишається ТЕМНИМ: без індиго, фіолетового, малинового і без світлої зони вгорі.
- Відблиски: 2–3 дуже тьмяні м'які плями (≈ 40–60 vmax), нейтральні сірі (білий ≈ 4–8%) і теплий помаранчевий ≈ `#FF9F0A` з прозорістю ≈ 0.10–0.18. Вони потрібні, щоб склу було що розмивати. Краї розмиваються через `radial-gradient(… → transparent)`. Якщо потрібен `filter: blur()`, то лише статичний.
- Рух ледь помітний: кожен відблиск повільно дрейфує (translate ≈ ±5–10 vmax) і «дихає» (scale ≈ 0.95–1.1, opacity у межах свого діапазону). Цикли 20–40 с, `ease-in-out`, `infinite alternate`; у кожного своя тривалість і затримка, щоб рух не синхронізувався.
- Анімуються лише `transform` і `opacity`. Не можна анімувати `filter`, `backdrop-filter`, `background*`, `top`/`left`/`width`/`height`. `will-change: transform` ставити тільки на відблиски.
- `prefers-reduced-motion: reduce` → `animation: none`: фон статичний, композиція та сама.
- Фолбек для скла: якщо `backdrop-filter` не підтримується (`@supports not …`) або ввімкнено `prefers-reduced-transparency: reduce`, картка отримує щільний темний фон ≈ `rgba(22, 22, 24, 0.92)` без розмиття. Контраст тексту при цьому не падає.

## Адаптивність
- Фіксованих брейкпоінтів немає: флюїдний mobile-first лейаут від 320 px.
- Картка: `width: min(100% - 32px, 40rem)`, тобто на мобільному вона на всю ширину з полями 16 px. Внутрішній відступ ≈ `clamp(20px, 5vw, 40px)`.
- Дисплей: `white-space: nowrap`, `line-height: 1`, `tabular-nums`; розмір залежить і від ширини, і від висоти. Орієнтир: `font-size: clamp(48px, min(22vw, 35dvh), 11rem)` (≈ 70 px на 320 px, ≤ 176 px на десктопі). Мінімум задано в px, а не в rem, щоб збільшений шрифт браузера не виштовхнув цифри за картку. На будь-якому в'юпорті цифри вміщаються у внутрішню ширину картки.
- Кнопки: у ряду щонайбільше дві, тож вони вміщаються в один ряд навіть на 320 px. Дві кнопки — рівні колонки. Одна — по центру, шириною як одна колонка або трохи ширша, але однаково для Start в idle і Reset на ліміті. Висота ряду однакова в усіх станах, щоб картка не стрибала. Зі збільшеним шрифтом браузера (2×) допустимий стовпчик. Висота кнопок ≥ 52 px, ширина ≥ 44 px, проміжок ≈ 8–12 px (не менше 8), лейбли не обрізаються; `touch-action: manipulation`; розмір тексту в `rem`.
- `<meta name="viewport" content="width=device-width, initial-scale=1">` без `user-scalable=no` і `maximum-scale`.
- Тестові в'юпорти: 320×568, 375×667, 390×844, 768×1024, 1280×800, 1920×1080, а також landscape 568×320 і 844×390. У landscape на телефонах вертикальний скрол допускається, горизонтальний — ні. Краще обійтися й без вертикального, ущільнивши відступи через `@media (max-height: 500px)`.

## Edge cases
- **Reset під час running**: одразу idle, `00:00`, відлік зупинено; «запізнілий» тік не повертає старе значення.
- **Подвійний Start** (дабл-клік, дабл-тап, утримання Enter): рівно один старт і жодної паузи на `00:00`. Після Start на тому ж місці з'являється Pause, тож друга дія в межах ≈ 400 мс ігнорується, а повтори keydown (`event.repeat`) не активують кнопку. Другий інтервал не створюється, `startedAt` не перезаписується, час не скидається і не прискорюється. Guard від повторного Start у reducer'і лишається, тож захист спрацює, навіть якщо два кліки прийдуть до ререндеру. Ефект з інтервалом має cleanup, тому StrictMode у dev не дає подвійного тіку.
- **Подвійний клік по Reset**: Reset зникає, Start переїжджає в центр і може опинитися під курсором. Друга дія в межах ≈ 400 мс ігнорується, тож таймер сам не стартує.
- **Клік у момент автостопу на ліміті**: слот Start/Pause зникає, і Reset стає єдиною кнопкою по центру. Вікно ≈ 400 мс діє й після автостопу, тож клік, націлений на Pause, не скине таймер.
- **Pause → Start**: продовжує з того ж значення, включно з дробовою частиною секунди. Якщо Pause натиснуто через 400–1000 мс після старту, буде paused з `00:00` і кнопками Start● · Reset.
- **Фонова чи згорнута вкладка**: браузер пригальмовує таймери (throttling), але після повернення значення одразу правильне, без «доганяння». За потреби перераховувати на `visibilitychange`.
- **Сон ОС** під час running: час сну зараховується.
- **Системний годинник переведено назад**: `elapsed` не стає від'ємним.
- **Після 59:59**: лічба не продовжується. На `59:59` автостоп: paused, помаранчевий `Limit reached`, на екрані лише Reset (помаранчева); `60:00` і більше ніколи не показується. Якщо ліміт минув, поки вкладка була у фоні, після повернення буде `59:59` у paused. (Рішення 1.)
- **Перезавантаження або вивантаження вкладки**: idle `00:00` (збереження стану поза скоупом).
- **Немає `backdrop-filter`** або ввімкнено `prefers-reduced-transparency`: щільний фон картки. **`prefers-reduced-motion`**: статичний фон і миттєва поява кнопок.
- **Збільшений шрифт браузера**: лейбли більшають, кнопки можуть стати стовпчиком, горизонтального скролу немає.
- Довгий текст, мережа, порожні дані, списки тут не застосовні.

## Доступність
- Кнопки — нативні `<button type="button">` з видимим текстом `Start` / `Pause` / `Reset`; accessible name = текст. Іконки й фон мають `aria-hidden="true"` (SVG ще й `focusable="false"`).
- Неактивних кнопок немає: показуються лише доступні дії, тож `disabled` і `aria-disabled` не використовуємо.
- Керування фокусом (фокус ніколи не падає на `body`):
  - Start ↔ Pause: фокус лишається на тому самому елементі слота;
  - Reset → idle: Reset зникає; якщо фокус був на Reset, він переходить на Start;
  - автостоп на ліміті: слот Start/Pause зникає; якщо фокус був на ньому, він переходить на Reset;
  - якщо фокус не на кнопках таймера, його ніхто не чіпає (автопереходи не крадуть фокус).
- Фокус на склі: `:focus-visible` → `outline: 2px solid` білого (світлого) кольору + `outline-offset: 3px`, контраст ≥ 3:1 до скла навколо, зокрема й довкола помаранчевої кнопки. Саме `outline`, а не `box-shadow`, бо його видно в forced-colors. `outline: none` без заміни заборонено.
- Дисплей і рядок стану НЕ є live-регіонами (без `aria-live` і live-ролей), тож кожна секунда не озвучується. Скрінрідер може прочитати їх звичайною навігацією.
- Live-регіон: візуально прихований `<p role="status">`. Він є в DOM з першого рендера (порожній), а текст змінюється тільки на переходах:

| Перехід | Текст |
|---|---|
| → running | `Timer running` |
| → paused (кнопка Pause) | `Timer paused at 05:23` (поточне значення) |
| → idle (Reset) | `Timer reset` |
| → paused на ліміті | `Maximum time reached. Timer paused at 59:59` |

- Сторінка: `<main>`, видимий `<h1>Timer</h1>` у заголовку картки, `lang="en"`, `<title>Timer</title>`.
- Контраст (WCAG 2.2 AA) вимірюється по найсвітлішій точці фону під карткою в будь-який момент анімації та в усіх станах кнопок. Увесь текст (сірі й помаранчеві капс-лейбли, лейбли кнопок, зокрема чорний на помаранчевій кнопці) ≥ 4.5:1; великі цифри ≥ 3:1 (і при вазі 300).
- Стан передається текстом лейбла, а не лише його кольором. Капс — лише через CSS `text-transform`, у DOM звичайний регістр.
- Враховуються налаштування користувача: `prefers-reduced-motion`, `prefers-reduced-transparency`, `forced-colors` (текст, кнопки і focus ring видимі).
- Зум 200% / 400% на десктопі не дає горизонтального скролу й не обрізає вміст.

## Поза скоупом
Builder цього не додає:
- кільце прогресу (як помаранчеве кільце на референсі), progress-смуга, будь-яка графіка часу (див. Рішення 3);
- елементи watchOS з референсу: `Close`, системний годинник, кнопка-дзвіночок, page dots, підпис тривалості `25 MIN`;
- зображення у фоні, будь-які ассети з референсів (Dribbble, Apple);
- реакція фону на курсор чи скрол, паралакс, пульсація чи світіння акценту, анімації цифр, блимання на паузі;
- теми й перемикач теми (зокрема світла тема), налаштування;
- звуки, вібрація, нотифікації;
- countdown, введення тривалості, пресети;
- збереження стану (localStorage, URL), відновлення після перезавантаження;
- кола (laps), спліти, історія;
- мілісекунди / десяті, години (`h:mm:ss`);
- гарячі клавіші;
- час у `document.title`, динамічний favicon;
- кілька таймерів, роутинг, бекенд, PWA/офлайн, аналітика, i18n;
- Storybook.

## Критерії приймання

### Логіка
1. Після завантаження стан idle: `00:00`, рядок стану `Idle`.
2. У кожному стані набір кнопок, текст рядка стану та його колір точно відповідають таблиці «Що на екрані»: idle — лише Start●; running — Pause● · Reset; paused — Start● · Reset; ліміт — лише Reset●. Неактивних кнопок і `aria-disabled` немає.
3. Після Start через ~1 с з'являється `00:01`, далі +1 щосекунди, без пропусків і «зависань» (у видимій вкладці).
4. Pause фіксує значення. Start після Pause продовжує з показаного значення, без скидання і без стрибка.
5. Reset у running і в paused одразу дає `00:00` і idle, відлік зупинено; старе значення не «блимає».
6. Дабл-клік / дабл-тап / утримання Enter на Start дають рівно один старт, без паузи на `00:00`: за 10 с реального часу дисплей додає 10 с (±1 с). Дабл-клік по Reset не запускає таймер. У коді є вікно ≈ 400 мс після переходу (одна константа), ігнорування `event.repeat`, guard від повторного старту в reducer'і; інтервал створюється в одному місці, ефект має cleanup.
7. Точність: після 5 хв running розбіжність з еталонним секундоміром ≤ 1 с (або перевірка коду: значення обчислюється з `Date.now()`, а не з лічильника тіків).
8. Фон: running → інша вкладка на ≥ 60 с → повернення: значення одразу правильне (±1 с).
9. 10 циклів Start/Pause поспіль: показаний час дорівнює сумарному реальному часу в running (±1 с).
10. Формат завжди `mm:ss` з ведучими нулями (`00:07`, `01:00`, `10:00`).
11. Ліміт (Рішення 1): на `59:59` автостоп: paused, помаранчевий `Limit reached`, на екрані лише Reset (помаранчева). `60:00` і більше не з'являється ніколи, зокрема після повернення з фонової вкладки. Ліміт задано однією константою (`3_599_000` мс). Перевірка: юніт-тест `formatTime`/reducer або тимчасово зменшена константа.

### Адаптив
12. На всіх тестових в'юпортах немає горизонтального скролу, час стоїть в одному рядку всередині картки, лейбли кнопок не обрізані. На портретних і десктопних в'юпортах картку видно повністю без вертикального скролу.
13. Ширина дисплея не змінюється зі зміною цифр (напр. `01:11` → `01:12`).
14. На мобільних в'юпортах картка на всю ширину з полями 16 px. Кнопки стоять в одному ряду навіть на 320 px: дві — рівні колонки, одна — по центру. Висота ряду кнопок однакова в усіх станах. Висота кнопок ≥ 52 px, проміжок ≈ 8–12 px (не менше 8), порядок основна → Reset.
15. Viewport meta не блокує зум; зум 200% на 1280 px не дає горизонтального скролу.

### Візуальний стиль і фон
16. Шрифт — Inter Variable (`@fontsource-variable/inter`): цифри білі, вага ≈ 300–400, `tabular-nums`; заголовок і рядок стану — дрібні капс-лейбли (uppercase через CSS). Картка — темне скло: білий ≈ 4–7% на чорному, `backdrop-filter: blur(≈24px)` (з `-webkit-` префіксом), border 1 px білий ≈ 8–12%, радіус ≈ 28 px, м'яка тінь. `backdrop-filter` на сторінці є лише в картки.
17. Помаранчева (≈ `#FF9F0A`) саме основна дія поточного стану: в idle і paused це Start, у running — Pause, на ліміті — Reset як єдина кнопка. Лейбл та іконка на ній чорні (≈ `#0a0a0a`). Reset поруч з основною дією — glass. Усі кнопки прямокутні (радіус ≈ 12–14 px, не pill), іконка ≈ 18 px + текст, без круглих бейджів. Поява/зникнення — fade/scale ≤ 200 мс тільки через `opacity`/`transform`; з `prefers-reduced-motion` — миттєво.
18. Фон — власний CSS: майже чорний (≈ `#000`–`#0a0a0a`) з радіальною віньєткою і 2–3 тьмяними відблисками (сірий, помаранчевий) з циклами 20–40 с; без індиго, фіолетового, малинового і без світлої зони; у проєкті немає зображень чи ассетів фону; у `@keyframes` змінюються лише `transform` і `opacity`.
19. DevTools → Rendering → Paint flashing: під час анімації фон не перемальовується (раз на секунду підсвічуються лише цифри). Performance з 4× CPU slowdown: фон не дає Layout/Paint на кожен кадр.
20. Емуляція `prefers-reduced-motion: reduce` у DevTools: фон повністю статичний.
21. Без `backdrop-filter` (`@supports not`) і при `prefers-reduced-transparency: reduce` картка має щільний темний фон ≈ `rgba(22, 22, 24, 0.92)`, текст ≥ 4.5:1.
22. Відблиски фону не додають скролу; при overscroll на мобільному не видно білого.

### Доступність
23. Tab ходить лише по видимих кнопках у порядку основна → Reset; Enter і Space активують; focus-ring видимий і на склі, і довкола помаранчевої кнопки (`outline` ≥ 2 px з offset, ≥ 3:1).
24. Фокус ніколи не падає на `body`. При Start ↔ Pause він лишається на тому самому елементі (слот не перемонтовується). Після Reset фокус переходить на Start, якщо був на Reset. На автостопі на ліміті фокус переходить на Reset, якщо був на слоті. Якщо фокус не на кнопках таймера, автопереходи його не чіпають.
25. Посекундно нічого не озвучується (дисплей і рядок стану без `aria-live`). На кожен перехід звучить рівно одне оголошення з таблиці в «Доступності» (перевірка через VoiceOver або код).
26. Контраст у найсвітлішій точці фону під карткою (перевірити статичний кадр і кілька моментів анімації): текст ≥ 4.5:1, зокрема чорний на помаранчевій кнопці в default/hover/active, а також помаранчеві й сірі капс-лейбли; цифри ≥ 3:1.
27. Стан не передається лише кольором (є текст). Іконки й фон мають `aria-hidden="true"`.
28. Є `<main>`, видимий `<h1>Timer</h1>`, `lang="en"`, `<title>Timer</title>`.
29. В емуляції forced colors (DevTools) текст, кнопки і focus ring видимі.

### Скоуп і якість
30. Нічого з «Поза скоупом» не реалізовано; залишків шаблону Vite немає; runtime-залежності — тільки `react`, `react-dom`, `@fontsource-variable/inter` (шрифт self-hosted, запитів до Google Fonts немає).
31. `npm run build` (разом із `tsc`) проходить без помилок; у консолі немає помилок і warnings.

### Контекстні кнопки (2026-10-02)
32. Картка не змінює висоту при переходах між станами (за стандартного розміру шрифту): ряд з однією і з двома кнопками однаково високий.

## Рішення
Затверджено користувачем; відкритих питань немає.
1. **Ліміт — зупинка на `59:59`.** Константа `3_599_000` мс. На `59:59` автостоп: paused, помаранчевий `Limit reached`, на екрані лише Reset (помаранчева). `60:00` і більше ніколи не показується.
2. **Шрифт — Inter Variable** через `@fontsource-variable/inter`: self-hosted, без запитів до Google Fonts. Фолбек `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`. Цифри — `font-variant-numeric: tabular-nums`, вага ≈ 300–400.
3. **Progress-смугу й кільце прогресу не додаємо**, зокрема помаранчеве кільце з нового референсу. Вони лишаються в «Поза скоупом».
4. **Рестайл (2026-10-02).** Новий референс — Apple Watch focus-таймер (скрін) + Dribbble «Leflow Focus Timer Website» (сторінка не відкрилась). Попередній референс (Risk Dashboard Cards) більше не актуальний. Що змінилося:
   - фон: майже чорний з віньєткою і ледь помітними сірими/помаранчевими відблисками; індиго, фіолетовий і малиновий не використовуються;
   - скло: темне (білий ≈ 4–7%), радіус ≈ 28 px;
   - кнопки: прямокутні (радіус ≈ 12–14 px, висота ≥ 52 px), іконка + текст; бейджі й pill-форма не використовуються;
   - акцент `#FF9F0A`: основна дія стану — помаранчева кнопка з чорним текстом; Reset поруч з нею — glass;
   - рядок стану й заголовок — капс-лейбли; кольорова крапка не використовується;
   - шрифт: Inter Variable (`@fontsource-variable/inter`); `@fontsource/ibm-plex-sans` не встановлювати.
5. **Контекстні кнопки замість неактивних (2026-10-02).** На екрані лише доступні дії: idle — Start●; running — Pause● · Reset; paused — Start● · Reset; ліміт — Reset●. Start і Pause — один і той самий `<button>`. Неактивні (приглушені) кнопки й `aria-disabled` не використовуються. Лейбл лишається `Pause`, як у ТЗ.
